# 项目规划文档
## 项目：AudioSwitch（音频设备快速切换工具）

---

## 1. 项目文件结构

```
audio-switcher/                      ← 项目总文件夹
├── docs/                            ← 所有文档（已完成的 PRD、技术方案都在这里）
│   ├── PRD.md
│   └── 技术方案设计文档.md
│
└── src/                             ← 源代码
    └── AudioSwitch/                 ← 主程序（一个 WPF 项目）
        ├── AudioSwitch.csproj       ← 项目配置文件（告诉电脑怎么编译）
        ├── App.xaml                 ← 应用入口（启动时最先执行的界面配置）
        ├── App.xaml.cs              ← 应用入口的代码
        ├── MainWindow.xaml          ← 主窗口界面（长得什么样）
        ├── MainWindow.xaml.cs       ← 主窗口的逻辑（点了按钮做什么）
        │
        ├── Core/                    ← 核心功能（跟设备打交道）
        │   └── DeviceSwitcher.cs       ← 切换默认麦克风/音箱
        │
        ├── Models/                  ← 数据模型（描述"一个设备"长什么样）
        │   └── AudioDevice.cs
        │
        ├── Services/                ← 辅助服务
        │   ├── DeviceService.cs        ← 设备枚举/过滤/缓存
        │   ├── TrayService.cs          ← 系统托盘
        │   ├── HotkeyService.cs        ← 全局快捷键
        │   ├── HotkeyManager.cs        ← 快捷键业务逻辑
        │   ├── SettingsPanelManager.cs ← 设置面板
        │   ├── SettingsManager.cs      ← 设置读写
        │   ├── ThemeService.cs         ← 主题切换
        │   ├── Logger.cs               ← 日志
        │   └── AutoStartService.cs     ← 开机自启动
        │
        └── Assets/                  ← 图标等资源
```

> 说明：这是"计划中的结构"，写代码时会按需创建，不会一次全建出来。

## 2. 开发步骤（从 0 到能用的完整路线）

我把整个项目拆成 **8 个小里程碑**，一次只做一个，每做完一个你都能看到进展：

| 步骤 | 目标 | 完成后你看到什么 |
|---|---|---|
| **1. 搭骨架** | 创建 WPF 项目，能跑起来 | 一个空白的窗口，双击能打开 |
| **2. 列出设备** | 代码能读取电脑上所有麦克风+音箱 | 窗口里显示你的设备列表 |
| **3. 切换设备**（核心） | 点一下就能切换默认设备 | 点哪个设备，哪个就变成默认 |
| **4. 界面美化** | 做成 Win11 高级风格 | 圆角、毛玻璃、好看的界面 |
| **5. 系统托盘** | 收进右下角托盘，右键可切换 | 软件最小化不占屏幕 |
| **6. 全局快捷键** | 按快捷键一键切换 | 不打开窗口也能切换 |
| **7. 开机自启动** | 提供开关，控制是否开机启动 | 设置页能开关自启动 |
| **8. 打包发布** | 生成 exe + 使用说明 | 一个能发给别人的 exe |

## 3. 开发顺序（为什么这样排）

**先核心、后外壳、再打磨**：

1. 先做"能不能切换设备"（第 2、3 步）——这是软件的命门，如果这个做不成，其他都白搭。
2. 再做"好不好用、好不好看"（第 4、5、6 步）——提升体验。
3. 最后做"方不方便拿到手"（第 7、8 步）——打包交付。

这样排的好处：**如果中途发现技术问题，能在投入最少的时候暴露出来**，不浪费后面做界面的功夫。

---

## 4. 预计会遇到的问题（提前打预防针）

1. **切换设备的底层接口较绕**：Windows 这个接口没官方文档，第一次实现可能报错。对策：直接参考 SoundSwitch 的开源代码，稳。
2. **WPF 做 Win11 高级感需要技巧**：默认界面朴素，要手写一些样式。对策：我会封装好样式，你不需要懂。
3. **托盘图标、快捷键这类"系统级"功能**：涉及 Windows API，细节较多。对策：一步一个脚印，逐个验证。
4. **虚拟麦克风可能显示成"停用"状态**：你的虚拟麦可能默认是禁用的，列表里可能看不到。对策：到时我们一起确认是否要"显示已停用设备"。
