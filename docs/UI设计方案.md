# AudioSwitch UI 设计方案

> 版本：v2.0 设计稿 ｜ 日期：2026-10-16 ｜ 状态：待评审  
> 设计目标：在保留用户既有操作习惯的前提下，把「打开 → 看一眼 → 切换 → 关掉」这个高频循环做到 3 秒内完成



---

## 1. 设计诊断：现有界面的四个问题

看完成现有实现后，我确认功能逻辑没有大问题，问题都在**视觉与信息架构**上：

| # | 问题             | 具体表现                                                            | 用户代价                 |
| - | -------------- | --------------------------------------------------------------- | -------------------- |
| 1 | **窗口尺寸与内容不匹配** | 900×520 的窗口只装 2–4 行设备，两张卡片下半部长期空白                               | 窗口像一张空表格，显得「没做完」     |
| 2 | **标题区信息噪音**    | 每张卡有「图标 + 标题 + 说明文字」三行 chrome，而说明文字（"点击切换默认麦克风"）只是在重复显而易见的交互    | 用户要先读 6 行废话才能看到第一台设备 |
| 3 | **状态表达不明确**    | 「当前默认设备」只靠一整行蓝色填充表达，容易被读成「我选中了它」；离线设备只靠变灰                       | 切换成功后不确定到底生效没有       |
| 4 | **设置项权重扁平**    | 5 组设置全是同等大小的卡片 + 裸 RadioButton，「外观主题」和「关闭行为」这种一次设完就不再碰的项，占了一半屏幕 | 设置页像一张长长的表格，找不到重点    |

**结论**：功能不缺，缺的是**层级**和**状态语义**。所以这版不做颠覆性重构，而是「减 chrome + 立语义 + 收尺寸」。

---

## 2. 设计原则

1. **一次只看一件事** —— 麦克风和音箱分时展示，但两者的当前状态始终可见（见分段控制器）
2. **状态必须可读** —— 「默认 / 在线 / 离线」三种状态，各自有独立的视觉编码，不靠颜色单独承担
3. **chrome 让位内容** —— 任何不承载信息的装饰性文字一律删除
4. **深浅双主题是一等公民** —— 所有颜色走 token，不允许硬编码
5. **尊重既有习惯** —— 「点一下设备就切换」这个核心交互不变，不增加确认步骤

## 3. 信息架构

### 3.1 主窗口（460 × 500，可横向拉伸至 720）

```
┌──────────────────────────────────────────┐
│ ◉ AudioSwitch              ─  □  ✕       │  38px  标题栏
├──────────────────────────────────────────┤
│ ┌────────────────┐ ┌────────────────┐    │
│ │ 麦克风          │ │ 音箱            │    │  56px  分段控制器
│ │ USB Microphone │ │ Realtek Audio  │    │  （同时显示两者当前默认）
│ └────────────────┘ └────────────────┘    │
│                                          │
│ 选择默认麦克风                  4 台设备  │  列表头
│ ┌──────────────────────────────────────┐ │
│ │ [mic] USB Microphone      ● 默认     │ │  52px  设备行
│ │       USB · 已连接                   │ │
│ └──────────────────────────────────────┘ │
│ ┌──────────────────────────────────────┐ │
│ │ [spk] 麦克风阵列（Realtek）     ●    │ │
│ │       主板声卡 · 已连接               │ │
│ └──────────────────────────────────────┘ │
│ ┌──────────────────────────────────────┐ │
│ │ [bt ] 蓝牙耳机麦克风         已断开   │ │
│ │       蓝牙 · 未连接                   │ │
│ └──────────────────────────────────────┘ │
├──────────────────────────────────────────┤
│ 开机自动启动  [开关]            [设置]    │  52px  底栏
└──────────────────────────────────────────┘
```

**关键决策：用分段控制器替代左右双卡片**

这是本方案最大的结构变化。理由：

- 用户的实际动作永远是「改麦克风」或「改音箱」之一，**不会同时改两个**。左右两栏强迫眼睛在两棵树之间来回跳。
- 分段控制器把「角色 + 该角色当前默认设备」压成一行，**两边的现状仍然一屏可见**，信息没有丢失。
- 单列后设备行获得完整宽度，长设备名（`Speakers (Realtek(R) Audio)`）不再需要省略或换行。
- 窗口从 900 宽收到 460 宽，视觉重量从「一张表」变成「一个面板」，和它「托盘常驻小工具」的定位匹配。

### 3.2 设置抽屉（340px，右侧滑入）

保留现有右侧抽屉的交互模式（用户已熟悉），重新组织内部层级：

```
┌─────────────────────────────┐
│ 设置                    ✕   │
├─────────────────────────────┤
│ 切换快捷键                   │  ← 高频：置顶
│ ┌─────────────────────────┐ │
│ │ 麦克风   Ctrl+Alt+F9 修改│ │
│ │ 音箱     Ctrl+Alt+F10 修改│ │
│ └─────────────────────────┘ │
│                             │
│ 外观主题                     │
│ ┌─────────────────────────┐ │
│ │ ◉ 跟随系统              │ │  ← 卡片式单选
│ │   随 Windows 深浅色切换  │ │
│ │ ○ 浅色                  │ │
│ │ ○ 深色                  │ │
│ └─────────────────────────┘ │
│                             │
│ 设备显示范围                 │
│ ◉ 智能模式    ○ 显示全部    │
│ ○ 仅 USB 与蓝牙              │
│                             │
│ 关闭按钮行为                 │
│ ◉ 每次询问  ○ 托盘  ○ 退出  │
├─────────────────────────────┤
│                恢复默认  保存│
└─────────────────────────────┘
```

**改动点**：

- 快捷键从「卡片 + 文本框 + 按钮」三件套压缩成一行内联显示，减少一半高度
- 单选从裸 RadioButton 改为**卡片式单选**（左侧圆环 + 标题 + 副标题），点按区域从 16px 扩大到整行 44px，触控友好
- 每个选项补一句副标题说明后果，用户不用猜「智能模式」是什么意思
- 按使用频率排序：快捷键（可能常改）→ 主题（偶尔）→ 显示范围（偶尔）→ 关闭行为（设一次就忘）

### 3.3 托盘菜单（238px）

```
┌────────────────────────┐
│ ◉ AudioSwitch          │
│ 麦克风 · USB Microphone│  ← 标题即当前状态
│ ✓ USB Microphone       │
│   麦克风阵列（Realtek） │
│   蓝牙耳机麦克风        │  ← 置灰，仍可点
│ ────────────────────── │
│ 音箱 · Realtek Audio   │
│   Realtek Audio        │
│ ✓ 显示器（AMD 高清音频）│
│ ────────────────────── │
│ ▤ 打开主窗口            │
│ ⤓ 退出                  │
└────────────────────────┘
```

**改动点**：

- 当前设备用 **✓ 勾选标记**而不是文字前缀，避免设备名被污染
- 分区标题直接带上当前默认设备名，右键一次就能看到两边现状，不必展开
- 「退出」用红色文字，和「打开主窗口」形成危险度区分
- **完整支持深色**（现有实现硬编码浅色，深色系统下托盘是一片白）

## 5. 组件规格

### 5.1 设备行 `DeviceRow`

```
高度 52px ｜ 内边距 9px 12px ｜ 圆角 10px ｜ 间距 11px
[32px 图标底] [弹性文字区] [尾部标记]
```

| 状态                | 视觉                                                                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **默认设备**          | 背景 `Bg.AccentSubtle`，边框 `Border.Accent`，图标底 `Bg.Surface` + `Accent.Text`，尾部「默认」徽章（`Accent.Text` 文字 + `Bg.Surface` 底 + `Border.Accent` 边） |
| **在线可选**          | 背景 `Bg.Surface`，边框 `Border.Hairline`，图标底 `Bg.SurfaceHover` + `Text.Secondary`，尾部仅一个 7px `Status.Online` 圆点                               |
| **离线**            | 整体 `opacity: 0.6`，元信息改「未连接」，尾部「已断开」标签（`Text.Tertiary` 文字 + `Bg.SurfaceHover` 底），无圆点                                                      |
| **hover**         | 背景 `Bg.SurfaceHover`（默认态为 `Bg.AccentSubtleStrong`）                                                                                       |
| **focus-visible** | 2px `Accent.Default` 外描边，offset 2px                                                                                                      |

**图标映射**（32px 圆角方底内 16px 线性图标，stroke 1.4px）：

| 总线/类型     | 图标              |
| --------- | --------------- |
| USB       | 麦克风/音箱 + USB 标记 |
| 蓝牙        | 蓝牙符号            |
| 主板声卡      | 扬声器             |
| 虚拟设备      | 显示器/芯片          |
| HDMI/显示输出 | 显示器             |

**可访问性**：默认状态同时用「填充 + 边框 + 徽章 + 勾选图标」四重编码，色弱用户不依赖颜色也能识别；离线状态额外有文字标签，不是只靠变灰。

### 5.2 分段控制器 `RoleSwitcher`

```
高度 56px ｜ 两等分 ｜ 间距 8px ｜ 圆角 10px
每段：[12px 角色标签 / 14px 当前默认设备名]
```

- 未选中：`Bg.Surface` + `Border.Hairline`，标签 `Text.Secondary`，设备名 `Text.Primary`
- 选中：`Bg.AccentSubtle` + `Border.Accent`，标签 `Accent.Text`
- 设备名超长省略号截断（`text-overflow: ellipsis`）
- 无设备时该段显示「无可用设备」，`Text.Tertiary`

### 5.3 开关 `Toggle`

```
38 × 21px ｜ 圆角 11px ｜ 滑块 16px
```

- 关：轨道 `#CBD1D8`（浅）/ `#3D4249`（深），滑块白/`#F2F3F5` 靠左
- 开：轨道 `Accent.Default`，滑块纯白靠右，margin 2.5px
- 带 `AutomationProperties.Name="开机自动启动"`

### 5.4 卡片式单选 `OptionCard`

```
最小高度 44px ｜ 圆角 9px ｜ 内边距 10px 12px
[17px 圆环] [标题 13px/500] [副标题 12px]
```

- 未选：`Bg.Surface` + `Border.Hairline`，圆环 1.5px `#5F6670`
- 选中：`Bg.AccentSubtle` + `Border.Accent`，圆环 `Accent.Text` + 内部 11px 实心点
- **整行可点**，不是只有圆环可点

### 5.5 快捷键行 `HotkeyRow`

```
高度 40px ｜ [角色名 13px] [键位胶囊] [修改按钮]
```

- 键位胶囊：`Bg.SurfaceHover` 底、`Radius.Sm`、内边距 4px 10px、13px/500
- 修改按钮：`Accent.Text` 文字 + `Border.Accent` 边框 + 透明底，12px

## 6. 状态与边界情况

| 场景               | 设计                                                                  |
| ---------------- | ------------------------------------------------------------------- |
| 列表中只有 1 台设备      | 正常渲染，行高不变，不出现空窗口                                                    |
| 设备全部离线           | 列表照常显示，全部走 offline 态；不弹错误                                           |
| 一个设备都没有          | 空状态：居中图标 + 「没有检测到麦克风」+ 一行说明（插入设备后自动出现 / 可切换到「显示全部」）                 |
| 设备名超长            | 名称单行省略号；把总线类型作为副标题保留，用户仍能区分                                         |
| 快捷键注册失败          | 保留现有气泡提示，但气泡标题改为「快捷键不可用」，正文给出具体冲突建议                                 |
| 窗口被拉到极窄（< 380px） | 分段控制器两段改为上下堆叠，设备行图标缩小到 28px                                         |
| 系统深色模式切换         | `ThemeMode.System` 下监听注册表 `AppsUseLightTheme` 变化，实时换肤（现有实现只在启动时读一次） |

## 7. WPF 落地要点

### 7.1 资源字典拆分

把 `MainWindow.xaml` 里那 500 行内联资源迁出去，按主题拆分：

```
src/AudioSwitch/
├── Themes/
│   ├── Colors.Light.xaml     # 浅色 token
│   ├── Colors.Dark.xaml      # 深色 token
│   ├── Controls.xaml         # 组件样式（DeviceRow / OptionCard / Toggle ...）
│   └── Typography.xaml       # 字号字重
```

`App.xaml` 合并字典，`ThemeService.Apply()` 改为**切换整个 ResourceDictionary**，而不是现在这样一个个往 `window.Resources` 里塞画刷——后者在 `DynamicResource` 已解析过的场景下容易漏刷新。

### 7.2 与现有代码的衔接

| 现有元素                                                | 新方案对应                                          | 改动量 |
| --------------------------------------------------- | ---------------------------------------------- | --- |
| `MicrophoneList` / `SpeakerList`                    | 合并为一个 `DeviceList` + `_currentRole` 字段         | 中   |
| `AudioDevice` record                                | 增加 `BusIcon`（图标枚举）与 `BusLabel`（本地化总线名）         | 小   |
| `DeviceItemTemplate`                                | 换成 `DeviceRow` 模板                              | 中   |
| `SettingsPanelManager.Initialize` 的 9 个 RadioButton | 换成 `OptionCard` + `Tag` 绑定                     | 中   |
| `TrayService.ModernMenuRenderer`                    | 颜色改从 `ThemeService` 取，深色时切换 `ModernColorTable` | 中   |
| `ThemeService.Apply(Window)`                        | 改为 `Apply(ResourceDictionary)`                 | 小   |

### 7.3 需要新增的代码

- `Models/DeviceKind.cs` —— 设备类型枚举 + 图标/标签映射
- `Services/SystemThemeWatcher.cs` —— 监听系统深浅色变化（`WM_SETTINGCHANGE`）
- `Themes/*.xaml` —— 上述四个资源字典

## 9. 验收标准

实现完成后按以下条目走查，全部通过才算落地：

### 10.3 已知偏差（如实记录）

**减少动画只降级了面板级过渡，没降级 120ms 级的 hover 微反馈。**
原因：WPF 样式内 Storyboard 的 `Duration` 不是依赖属性，无法在运行时统一绑定开关；要全量瞬时只能把 hover 改成即时 Setter（丢掉淡入）。
当前实现：抽屉滑入/滑出、遮罩淡入已按 `MotionService.IsReducedMotion` 瞬时化；设备行 hover 保留 120–180ms 透明度淡入（非位移、无缩放，不触发前庭不适）。
如需严格全量瞬时，把 `Controls.xaml` 中两处 hover Storyboard 换成 Setter 即可，我可以改。

### 10.4 与设计稿的有意差异

- **设备行图标按角色（麦克风/音箱）而非按总线**：所有麦克风图标一致更利于扫视，总线类型以副标题文字呈现（「USB · 已连接」）
- **`<380px` 分段堆叠规则未实现**：`MinWidth=380` 从规格上杜绝了该场景
- **快捷键校验失败改走托盘气泡**：胶囊里塞长文案会换行破版
- **`Ellipse` 圆点/徽章用字形与形状绘制**，未导出独立图标资产（见第 8 章）
